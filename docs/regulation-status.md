# Проверка требований кейса

Источник: `Автодиспетчер_презентация 1.10.pdf`, 11 физических страниц (нумерация слайдов
в документе пропускает №5). Таблица относится к учебному прототипу в ветке `integrated`.

| Требование | Реализация / проверка |
|---|---|
| Mock-данные, положение поездов, сигналы, стрелки, расписание | 8 поездов; позиции и энергия native logic; 13 условных горловин; нормализация всех групп данных |
| Планирование с приоритетами и ограничениями | CP-SAT, станционные/главные пути, горловины; независимый валидатор, сохранение начатых рейсов |
| Автоведение / рекомендации скорости | Физический профиль на каждом перегоне, ограничения, тяга и вспомогательная энергия |
| Сбой → пересчёт → альтернативы с индексом | 19 сценариев; три стратегии; блокировка применения устаревшего результата |
| Пять составляющих индекса | График, пропуск, энергия, конфликты, точность; единые нормы для вариантов |
| Настраиваемая формула, веса, пороги | Две формулы, пять весов, нормы и пороги; admin API + UI, сохранение после перезапуска |
| Норма / Внимание / Критично | Категория факта и прогноза; предварительный индекс до прибытия |
| Отдельный приём/нормализация, шина событий | Отдельный FastAPI-сервис, SI-нормализация, упорядоченный буфер с offset и дедупликацией; имитация брокера |
| История 24–72 часа, REST и WebSocket | SQLite, по умолчанию 48 часов; поток записи; Swagger; роль viewer читает историю |
| Поток не реже 1 Гц | Плановая частота 2 Гц; измерено 2,0036 Гц в отдельном сервисном запуске |
| Перепланирование ≤5 с | Четыре опыта: от запроса до получения вариантов 3,36–4,28 с; все планы проверены и применены |
| 5–10 одновременных проблем | Атомарные пакеты 5 и 10 сбоев + готовый сценарий 10; три допустимых варианта в каждом опыте |
| Событие → видимое обновление <500 мс | **Сбор замеров реализован; подтверждение в видимом браузере не получено.** Инструмент браузера этого сеанса недоступен. Скорость API не доказывает скорость отрисовки |
| Без деградации UI при 5–10 сбоях | API/WS под нагрузкой проверены; максимальная пауза потока 557 мс при целевом интервале 500 мс. **Визуальную плавность ещё нужно проверить в браузере** |
| Базовая авторизация и ограничения настройки/оптимизации | По умолчанию вход обязателен; viewer / dispatcher / admin; HTTP и WebSocket, тесты запретов |
| Веб-карта, график, индекс, профиль | React-панель и карта era подключены к одной модели; новая функциональность frontend согласована |
| Воспроизведение 5–15 минут, PDF или CSV | Последние 15 минут модельного времени, CSV |
| Git, инструкция, архитектура, презентация 10–12 слайдов | Документация и Mermaid, PPTX на 12 слайдов, сценарий живого показа |
| Видео или живой показ | Подготовлен воспроизводимый живой показ; видеозапись не создавалась |

## Измерения

Полные данные: [regulation-benchmark.json](regulation-benchmark.json).
Замер проводился локально с отдельным ingestion-сервисом и demo-авторизацией тестового
запуска; базовая авторизация отдельно проверяется тестами и обычным запуском.

| Испытание | Запрос → варианты | Максимальный ответ /api/state |
|---|---:|---:|
| Одно закрытие | 3,38 с | 41 мс |
| Пакет 5 сбоев | 3,36 с | 31 мс |
| Пакет 10 сбоев | 3,37 с | 26 мс |
| Новый сценарий с 10 сбоями | 4,28 с | 96 мс |

Это результат на данном компьютере, а не гарантия срока на любой машине.
Для проверки кадра откройте видимую вкладку `/dispatcher/`, запустите
`python -m integration.benchmark` и проверьте `ui_event_to_paint` и `/api/logic/performance`.
Если `samples` пустой, проверка не выполнена. Лимит — строго меньше 500 мс.

## Границы достоверности

- Точное число эксплуатационных путей, взаимозависимости реальных стрелок, блок-участки
  и суточный график неизвестны. Горловины и нагрузка явно синтетические. Это согласовано
  с разрешённым регламентом mock-режимом, но не подтверждает точность реальной сети КТЖ.
- Автоведение здесь — расчёт рекомендаций в симуляторе. Прототип не управляет локомотивом.
- Экономика использует заданные ставки и допустимые сравнимые планы; фактическая денежная
  экономия без эксплуатационных данных не доказана.
- Шина событий имитируется в памяти, не даёт гарантий Kafka. Длительная история — в SQLite.
- Полное соответствие ограничениям UI по времени пока не подтверждено. До очной защиты
  нужен замер в видимом браузере на машине демонстрации.

## Проверки сборки

- Python: **222 теста прошли**, включая независимые параллельные пути, горловины, роли и сохранение настроек.
- TypeScript и production-сборка React проходят; JavaScript: 3 проверки координат.
- Собран образ Docker; два контейнера (API и ingestion) прошли smoke: 8 поездов,
  3 плана за 3,859 с, применение, native-валидация, CSV.
- Обычный локальный запуск с авторизацией прошёл тот же smoke: 3 плана за 3,466 с.
- Презентация: 12 слайдов, редактируемые таблицы/схема, проверены структура и рендер.

Предупреждения инструментов: deprecated httpx-адаптер TestClient и крупные Vite chunks.
Они не препятствуют проверкам, но размер frontend стоит учитывать при первом открытии.
