# Как railsim подключён к алгоритмам

Исходная папка: `/home/sam/Documents/railsim`. Прочитаны все 16 файлов.
Их точная копия находится в `vendor/railsim`, контрольные суммы — в
[source_manifest.json](../data/railsim/source_manifest.json).
Исходная папка не изменена. Адаптеры и изменения относятся к проекту KTZH.

## Файлы и назначение

| Исходный файл | Как используется |
|---|---|
| `README.md` | Сохранены описание задач и ограничения исходной модели |
| `config.py` | Сохранён пустой шаблон; заполненная конфигурация создаётся адаптером |
| `requirements.txt` | SimPy и pandas подключены к пакету; scipy и matplotlib — через extra `realism` |
| `main.py` | Работает с экспортированным `output/railsim/configuration.py` |
| `railsim/__init__.py` | Исходный Python-пакет включён в установку проекта |
| `util.py` | Те же флаги функций и общие случайные числа |
| `line.py` | Неизменённые FIFO и SmartDispatcher в событийной симуляции |
| `trains.py` | Движение, вероятности отказов, отцепки, остановки и трассы |
| `hazards.py` | Генерация угроз; те же правила обнаружения, окончания погоды и ремонта |
| `simulation.py` | Прогоны на общем расписании и общих случайных событиях |
| `energy.py` | Сохраняется исходная оценка энергии; формула Davis перенесена в физические профили и проверена тестом |
| `economics.py` | Таблица KPI и вклад функций; автоматическое годовое масштабирование в адаптере отключено |
| `plots.py` | Графики исполненного движения и KPI; адаптер задаёт подписи для коридора |
| `validate.py` | Проверка полноты конфигурации; адаптер добавляет проверки диапазонов и конечности чисел |
| `terminals.py` | Сохранён; порт и граница выключены для Кокшетау — Нурлы Жол |
| `wagons.py` | Сохранён; распределение порожних вагонов можно включить с собственными supply/demand, международный обмен выключен |

Входных фактических чисел в исходном `config.py` не было: значения `None`
и пустые списки. Поэтому [railsim.example.json](../config/railsim.example.json)
содержит учебные параметры с `calibration_status=illustrative`.
Геометрия остаётся из OSM, движение — синтетическое. Реальный износ, вероятности
происшествий, расположение переездов, уклоны и эффект датчиков не установлены.

## Два связанных расчёта

1. `realism` запускает исходную событийную модель. `baseline` — FIFO,
   `auto` — исходный SmartDispatcher с включёнными функциями. Они видят одинаковые
   поезда и случайные числа. Это не замена SmartDispatcher на CP-SAT.
2. Адаптер экспортирует закрытия и временные ограничения в обычный `Scenario`.
   Его принимает наш CP-SAT с конечной вместимостью станций, раздельными главными
   путями, физическими профилями и независимой проверкой.

Файл `shared_events.json` содержит исходные угрозы и случайные числа отказов
для поездов. `baseline_constraints.json` и `auto_constraints.json` содержат
ограничения после реакции соответствующей политики. Это повторный расчёт
известного набора событий, а не предсказание будущих происшествий.

Минимум — **пять поездов**, по умолчанию — **восемь**: шесть пассажирских
и два грузовых в обоих направлениях. Пассажирские идут до Нурлы Жол,
грузовые ограничены Астаной-1. В исходной модели используются фиксированные
отправления из нашего сценария; пуассоновская генерация не может случайно
уменьшить число поездов ниже пяти. `SIM_DAYS` повторяет этот набор по дням;
экспорт в CP-SAT относится к исходному набору и его горизонту.

## Сценарии проблем

Семь прежних случаев сохранены. Дополнительно доступны:

| Имя в CLI | Смысл ограничения и реакции |
|---|---|
| `railsim_rail_defect` | Обнаруженный дефект рельса: закрытие до окончания ремонта |
| `railsim_theft` | Хищение деталей: закрытие для восстановления пути |
| `railsim_flood` | Размыв: закрытие на время явления |
| `railsim_snow` | Ограничение скорости во время снежного заноса |
| `railsim_sand` | Ограничение скорости из-за песка |
| `railsim_heat` | Температурное ограничение скорости |
| `railsim_loco_failure` | Поезд удерживает путь на время ожидания помощи |
| `railsim_wagon_defect` | Выявленный дефект: отцепка и перенос готовности на станции |
| `railsim_crossing` | Закрытие из-за происшествия на переезде |
| `railsim_people` | Закрытие из-за происшествия с людьми на пути |
| `railsim_maintenance` | Заранее объявленное ремонтное окно |
| `railsim_derailment` | Ожидание восстановления и блокирование других путей перегона |

Эти 12 случаев — управляемые проверки: ограничения задаются на будущем
отрезке маршрута, чтобы сохранить уже начатое движение. В случайной модели
частоты и исходы генерируются отдельно; единичная демонстрация не является
оценкой аварийности.

Для погоды сохраняется правило исходника: ограничение определяется в момент
въезда. После конца интервала новые поезда получают обычную скорость.
Отказы представлены ожиданием на границе входа в зарезервированный перегон;
место фактического повреждения, эвакуация и геометрия схода не моделируются.

В профилях ожидание помощи имеет нулевую скорость и вспомогательное потребление.
Тяговая энергия на этом интервале не начисляется. При восстановлении всего
перегона запрет для соседних путей связан со временем движения нового плана.
Это исключает возможность сдвинуть поезд, оставив закрытие на старом времени.

## Запуск

```bash
python -m pip install -e '.[dev,realism]'
python -m backend.app.cli generate --trains 8
python -m backend.app.cli simulate --trains 8
python -m backend.app.cli realism --trains 8 --runs 3 --seed 42 --plots --attribution
python -m backend.app.cli solve output/railsim/auto_constraints.json --output output/railsim/planner_result.json
python -m backend.app.cli validate output/railsim/auto_constraints.json output/railsim/planner_result_plan.json
```

Быстрая проверка пяти поездов:

```bash
python -m backend.app.cli simulate --trains 5 --incidents railsim_snow railsim_loco_failure
```

Для своей конфигурации событийной модели используйте
`realism --profile <файл.json>`. Экспорт включает выбранные коэффициенты Davis
и уклоны. Проверить совместимость с оригинальным запуском:

```bash
python vendor/railsim/main.py --config output/railsim/configuration.py --check
```

## Результаты и ограничения

- `output/corridor/<сбой>/resolution.json` — старые нарушения, новые планы,
  скорость и метрики; `*_track_load.csv` — загрузка путей.
- `output/railsim/report.json` — средние KPI, параметры и ограничения модели.
- `runs.csv`, `summary.csv`, `attribution.csv` — прогоны и сравнения.
- `shared_events.json`, `trajectories.json` — исходные события и исполненное движение.
- `configuration.json/.py` — воспроизводимая заполненная конфигурация.
- `string_diagram.png`, `kpi.png` — графики из исходного модуля.

Станции в исходном railsim имеют бесконечную вместимость. Автоблокировка там
моделируется количеством одновременно находящихся на перегоне поездов, без
проверки отдельных блок-участков и межпоездного интервала. В учебной конфигурации
выбрана полуавтоблокировка; наш CP-SAT продолжает резервировать отдельный главный
путь целиком между станциями.

Подсказка скорости в исходнике оценивает предотвращённые остановки через
величину ожидания и не пересчитывает саму траекторию. Поэтому `smoothed_stops`
подписан как модельная оценка. Энергия исходной событийной модели и энергия
физических профилей — разные оценки; они не суммируются.

Перекрывающиеся закрытия при экспорте KPI объединяются. Исходная сумма сохранена
в `closure_hours_raw_sum`. Годовая прибыль и снижение тарифов из короткого
учебного прогона не выводятся. Ущерб происшествий в параметрах не оценён.

Мониторинг, ремонт по состоянию, детекторы вагонов и камеры сохранены в исходных
функциях, но по умолчанию выключены: наличие оборудования и его эффект не
подтверждены. Произвольная процентная экономия тяги и рекуперация также равны нулю.
Включены `smart_dispatch`, `speed_advisory`, `maintenance_windows`.

Все ограничения точности инфраструктуры сохраняются: реальные станционные
пути и режимы движения требуют эксплуатационных схем. Итоговые проверки
приведены в [verification.md](verification.md).
